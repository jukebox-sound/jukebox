=head1 NAME

jukebox-plugins - plugin format and lifecycle for jukebox

=head1 DESCRIPTION

jukebox plugins are Perl source files discovered at startup and loaded
on demand.  A plugin consists of a metadata block understood by the
plugin scanner and a Perl package named from the plugin identifier.

This manual documents the contract implemented by the jukebox plugin
loader.  Existing modules under F</usr/share/jukebox/plugins/> are the
best examples for feature-specific APIs and Gtk2 integration.

=head1 DISCOVERY

Files ending in C<.pm> or C<.pl> are searched in this order:

=over

=item *

The system plugin directory, normally F</usr/share/jukebox/plugins/>.

=item *

The user's F<$XDG_CONFIG_HOME/jukebox/plugins/> directory.

=item *

Directories supplied with B<jukebox -searchpath>.

=back

A plugin is first scanned for metadata.  Its Perl code is evaluated only
when jukebox activates that plugin.

=head1 METADATA

The first significant block in a plugin file identifies the plugin.  The
usual form is:

  =for gmbplugin EXAMPLE
  name    Example
  title   Example plugin
  version 1.0
  author  Example Hacker <hacker@example.invalid>
  desc    Demonstrates the plugin interface.
  req     perl(Some::Module, package-name) exec(tool, package-name)
  =cut

The identifier after C<gmbplugin> must begin with a letter and otherwise
contain word characters.  The same identifier is used for the Perl
package and the C<PLUGIN_ID> option that enables the plugin.

Recognized metadata includes:

=over

=item C<name>

Required display name.  A metadata block without C<name> is ignored.

=item C<title>

Longer title displayed in the preferences interface.

=item C<version>

Plugin version.  When duplicate plugin identifiers are discovered,
jukebox keeps the newer unloaded version unless one is already loaded.

=item C<author>

Author attribution.  The key may occur more than once.

=item C<desc>

Description.  Multiple C<desc> lines are concatenated.

=item C<req>

Optional runtime requirements.  The loader understands the following
forms:

  perl(Module::Name, suggested-package-names)
  exec(program, suggested-package-names)
  file(/absolute/path, suggested-package-names)

The suggested package-name part is optional and is shown to the user
when a requirement is missing.

=item C<url>

Optional project or documentation URL displayed with plugin metadata.

=back

=head1 PACKAGE AND LIFECYCLE

For plugin id C<EXAMPLE>, the implementation package must be:

  package GMB::Plugin::EXAMPLE;

The loader invokes lifecycle methods in that package when they exist.

=over

=item C<Init()>

Optional early initialization.  During normal startup it is called after
saved options have been read and before the music library has finished
loading.  When a plugin is enabled interactively, C<Init()> is called
before C<Start()>.

=item C<Start($startup)>

Optional activation hook.  It is called once the library is available,
or immediately when the user enables a plugin.  Plugins normally create
watches, register commands, or initialize runtime state here.

=item C<Stop()>

Optional deactivation hook.  Remove commands, event watches, timers,
windows, and other resources owned by the plugin here.

=item C<prefbox()>

Return the Gtk2 widget shown on the plugin's preferences page.  Loaded
plugins are expected to provide this method because the preferences
interface calls it directly.

=back

A minimal plugin therefore looks like:

  =for gmbplugin EXAMPLE
  name    Example
  title   Example plugin
  desc    Minimal plugin example.
  =cut

  package GMB::Plugin::EXAMPLE;

  sub Start {
      # establish runtime state
  }

  sub Stop {
      # release runtime state
  }

  sub prefbox {
      return Gtk2::Label->new('No options');
  }

  1;

=head1 OPTIONS

Plugin settings live in the global C<%::Options> hash and are persisted
inside C<jukeboxrc>.  The established convention is to give each plugin
a private prefix:

  use constant OPT => 'PLUGIN_EXAMPLE_';

  ::SetDefaultOptions(
      OPT,
      enabled_thing => 1,
      label         => 'value',
  );

C<::SetDefaultOptions()> only supplies a value when the corresponding
option is not already defined, so saved user choices are preserved.

Preference helper functions such as C<::NewPrefCheckButton()>,
C<::NewPrefEntry()>, and C<::NewPrefSpinButton()> bind common Gtk2
controls to entries in C<%::Options>.  Plugins may also build ordinary
Gtk2 widgets directly when their configuration is more structured.

=head1 EVENTS

C<::Watch()> subscribes an object or callback to a jukebox event:

  ::Watch($object, PlayingSong => \&song_changed);

For Gtk2 objects, jukebox automatically connects object destruction to
watch cleanup.  C<::UnWatch_all($object)> explicitly removes all event
and filter watches associated with an object.

A plugin should release long-lived watches during C<Stop()> when their
owner is not naturally destroyed with the plugin UI.

Event names are part of jukebox's internal API rather than a separately
versioned protocol.  Search existing plugins and C<HasChanged()> calls
in the source tree before depending on a particular event.

=head1 COMMANDS

Plugins can register commands in C<%::Command>.  For example:

  $::Command{ExampleAction} = [\&run_action, 'Example action'];

A plugin that adds a command must remove it again from C<%::Command> in
C<Stop()>.  Registered commands can be used by layouts, key bindings,
the command FIFO, and B<jukebox -cmd> according to the command's
implementation.

Use B<jukebox -listcmd> to inspect the commands registered by the
running build and enabled plugin set.

=head1 COMMON JUKEBOX HELPERS

The following helpers are used by in-tree plugins and are useful when
the corresponding behavior is required:

=over

=item C<::ReplaceFields($song_id, $template)>

Expand jukebox field variables in a template for a song.

=item C<::ReplaceFieldsAndEsc($song_id, $template)>

Expand field variables and escape substituted values for Pango markup.

=item C<::PangoEsc($text)>

Escape text before embedding it in Pango markup.

=item C<Songs::Get($song_id, @fields)>

Read song fields from the library.

=item C<Songs::Get_gid($song_id, $field)>

Return the group id for a grouped field such as C<artist> or C<album>.

=item C<Songs::MakeFilterFromGID($field, $gid)>

Construct a song filter for a grouped-field identity.

=back

These are source-level APIs used by the bundled plugins, not a stable
external ABI.  A plugin intended to track jukebox development should be
tested against the target jukebox version.

=head1 USER INTERFACE

jukebox uses Gtk2.  Plugin preferences and plugin-provided context views
should therefore use Gtk2 widgets and follow GTK state and theme
semantics rather than hard-coding foreground/background colors.

When displaying library entities obtained from an external service,
keep remote metadata distinct from local library identity.  Resolve the
remote entity to local data before exposing local-only operations such
as filtering or queue construction.

=head1 DEVELOPMENT WORKFLOW

A practical workflow for a new plugin is:

=over

=item 1.

Start from the smallest bundled plugin with a similar lifecycle.

=item 2.

Choose a unique metadata id and matching C<GMB::Plugin::ID> package.

=item 3.

Use a private C<PLUGIN_ID_> option prefix and declare defaults before
runtime initialization.

=item 4.

Acquire runtime resources in C<Start()> and release them in C<Stop()>.

=item 5.

Return a Gtk2 preferences widget from C<prefbox()>.

=item 6.

Run jukebox with B<-debug> while developing and use B<-searchpath> to
load the development copy without installing it system-wide.

=back
